# 架构说明

## 数据流

```text
72 道镜像题
  ├─ 学生自评 ──> 独立自我画像 ──> 发展探索方向
  └─ 观察者他评 ─> 独立他人画像
                         │
两个画像并列比较 ────────┴─> 共同高点与中性差异
                                   │
背景信息 + 三类画像 ──────────────> 专业解读资料包
```

双视角比较层只生成共同点和差异，不创建合并画像。探索规则只消费学生自评画像，专业资料包则明确保留各数据来源。

## 模块边界

- `data/assessment.ts`：版本化题目数据。
- `lib/scoring.ts`：从逐题答案生成单一视角画像。
- `lib/comparison.ts`：比较两个已完成画像。
- `lib/exploration.ts`：从自评信号匹配探索方向。
- `lib/storage.ts`：为本地存储与 Supabase REST 提供同一接口。
- `lib/professional-export.ts`：生成稳定的结构化输出和可下载文本。

页面只负责流程编排和展示。计分、比较、持久化和导出逻辑相互独立，便于后续测试与替换。

## 路由设计

测评和结果页使用固定路径，并将本地记录 ID 放在 URL fragment 中。Fragment 不会发送给服务器，可减少边缘安全规则误判，也避免记录 ID 出现在普通服务器访问日志中。

观察者邀请使用短码路径。正式跨设备部署必须使用安全的服务端令牌模型，不能把短码本身视为充分授权。
